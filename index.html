Métodos de Búsqueda en Estructuras de Datos

Localizar información con precisión define la eficiencia de cualquier sistema de cómputo. Desde el recorrido lineal sobre arreglos y listas enlazadas hasta la partición logarítmica y el acceso directo mediante funciones de dispersión, cada método responde directamente a cómo se organizan los datos en memoria.

Contexto estructural y modularidad

La estructura en memoria condiciona la búsqueda

Bajo el principio clásico Programación = Estructuras de Datos + Algoritmos, no es posible elegir un algoritmo de búsqueda sin observar cómo residen los datos en memoria principal. Las colecciones se dividen en estructuras contiguas (como vectores o arreglos estáticos en posiciones adyacentes) y estructuras enlazadas (nodos vinculados mediante punteros o referencias sin requerir contigüidad física).

Asimismo, el paradigma de Tipos de Datos Abstractos (TDA) y la modularidad en lenguajes orientados a objetos como C# separan la interfaz pública de la operación (qué buscamos) de su implementación interna (cómo recorremos la estructura), permitiendo sustituir un vector por una lista enlazada o una tabla hash sin romper el resto de la aplicación.

Sección 6.1 · Recorrido lineal

6.1 Búsqueda Secuencial (Lineal)

Mejor O(1) · Peor O(n)

La búsqueda secuencial (o búsqueda lineal) es el método más directo y universal para localizar un elemento objetivo x dentro de una colección. Consiste en inspeccionar los elementos uno por uno, en orden consecutivo desde el inicio de la estructura hasta localizar una coincidencia o alcanzar el final sin éxito.

A diferencia de otros métodos, no exige que los datos estén ordenados. En arreglos contiguos admite una mejora clásica llamada búsqueda con centinela: se coloca el valor buscado al final (en A[n]) para eliminar la comprobación del límite en cada iteración del bucle y verificar al salir si se halló antes del centinela. En listas enlazadas desordenadas suele emplearse además la heurística de mover al frente (move-to-front), reubicando el nodo encontrado al inicio para acelerar consultas repetidas tipo caché.

Algoritmo paso a paso

  1. 01 Inicialización: Posicionar el cursor al principio: índice i = 0 en un arreglo, o puntero auxiliar P = PRIMERO en una lista enlazada.
  2. 02 Condición de límite: Comprobar que no se haya superado el final (i < n o P != null). Si se alcanzó el fin, terminar devolviendo no encontrado (-1 o null).
  3. 03 Comparación: Evaluar si el valor actual (datos[i] o P.Dato) es igual al objetivo x.
  4. 04 Éxito o avance: Si coincide, retornar la posición i (o la referencia P). De lo contrario, avanzar (i++ o P = P.Siguiente) y repetir desde el paso 02.
  5. 05 Variante ordenada (optimización): Si la estructura está ordenada ascendentemente y el valor actual supera a x, se puede abortar tempranamente como búsqueda fallida.

Análisis de Complejidad

  • Mejor caso — O(1): El elemento buscado se ubica exactamente en la primera posición (índice 0 o cabeza de la lista); basta 1 comparación.
  • Caso promedio — O(n): Con probabilidad uniforme, requiere (n + 1) / 2 comparaciones (~500 pasos en 1,000 elementos).
  • Peor caso — O(n): El dato está al final o no existe en la colección; exige recorrer todos los n elementos.
  • Complejidad espacial — O(1): Solo utiliza una variable índice o un puntero temporal P.

Uso en listas enlazadas

Las listas enlazadas simples y dobles carecen de acceso aleatorio por índice. Por ello, incluso si una lista enlazada contiene datos ordenados, su búsqueda base sigue siendo secuencial O(n) siguiendo los enlaces SIG(P).

Ventajas

  • No requiere ordenamiento previo de los datos.
  • Implementación trivial y bajo consumo de memoria O(1).
  • Funciona tanto en estructuras contiguas (arreglos) como enlazadas (listas simples, dobles o circulares).
  • Excelente rendimiento en arreglos muy pequeños por su localidad de caché secuencial.

Desventajas

  • Ineficiente para colecciones grandes: el tiempo crece linealmente con n.
  • En listas enlazadas presenta menor localidad espacial que en arreglos contiguos debido a saltos de puntero en memoria.
  • Realiza en promedio n / 2 comparaciones aun cuando existan índices alternativos posibles.

Casos de uso frecuentes

  • Listas pequeñas (decenas de elementos) donde ordenar cuesta más que buscar.
  • Listas enlazadas dinámicas con inserciones frecuentes sin índice auxiliar.
  • Datos que llegan en flujo sin orden y se consultan de forma esporádica.

Sección 6.2 · Divide y vencerás

6.2 Búsqueda Binaria

Complejidad O(log n)

La búsqueda binaria aplica el paradigma algorítmico de divide y vencerás. Al igual que cuando una persona abre una agenda o diccionario por la mitad y decide si retroceder o avanzar alfabéticamente según la letra observada, este método compara el elemento central del intervalo actual contra el valor buscado y descarta la mitad imposible en una sola operación.

Prerrequisito fundamental

Para que la búsqueda binaria sea correcta y eficiente se requieren dos condiciones estrictas: 1) los elementos deben estar previamente ordenados (ascendente o descendentemente), y 2) la estructura debe permitir acceso aleatorio O(1) por índice (como un arreglo o vector contiguo).

Cálculo seguro del índice central

En cada iteración se delimita el subarreglo mediante los índices bajo y alto. Aunque algebraicamente el punto medio es (bajo + alto) / 2, en lenguajes con enteros de tamaño fijo como C# (Int32) la suma bajo + alto puede producir un desbordamiento (overflow) en arreglos masivos. La forma segura estándar es:

medio = bajo + (alto - bajo) / 2   // División entera (redondea hacia abajo)

Algoritmo paso a paso

  1. 01 Delimitar intervalo: Asignar bajo = 0 y alto = n - 1.
  2. 02 Condición de paro: Mientras bajo <= alto, el subarreglo de búsqueda aún contiene al menos un elemento. Si bajo > alto, el valor no existe y se devuelve -1.
  3. 03 Calcular pivote central: Obtener medio = bajo + (alto - bajo) / 2.
  4. 04 Evaluar y dividir: Si datos[medio] == x, retornar medio. Si x < datos[medio], descartar la mitad derecha ajustando alto = medio - 1. Si x > datos[medio], descartar la mitad izquierda ajustando bajo = medio + 1.
  5. 05 Repetir o retornar: Continuar iterando (o invocando recursivamente BuscarRecursivo sobre el nuevo subarreglo) hasta encontrar x o agotar el intervalo.

Análisis de Complejidad

  • Mejor caso — O(1): El elemento buscado coincide con el primer pivote central evaluado.
  • Caso promedio y peor caso — O(log₂ n): Cada comparación reduce el espacio restante a la mitad (n, n/2, n/4, ..., 1). El máximo de pasos es ⌊log₂ n⌋ + 1.
  • Espacio (Iterativa vs. Recursiva): La versión iterativa usa memoria auxiliar O(1); la recursiva consume O(log n) en la pila de llamadas del sistema.

Escala logarítmica en acción

Comparaciones en el peor caso conforme crece n:

  • n = 16  →  máx. 5 pasos
  • n = 1,000  →  máx. 10 pasos
  • n = 1,000,000  →  máx. 20 pasos

Ventajas

  • Velocidad drásticamente superior a la búsqueda lineal en conjuntos medianos y grandes.
  • Comportamiento determinista y predecible: acotado estrictamente a O(log n).
  • Versión iterativa libre de sobrecarga en pila de llamadas y con espacio constante O(1).

Desventajas

  • Exige que el arreglo esté ordenado; ordenar desde cero cuesta O(n log n).
  • Mantener un arreglo contiguo ordenado ante inserciones y borrados frecuentes cuesta O(n) por desplazamiento de elementos.
  • Ineficaz en listas enlazadas puras al no poder saltar al índice medio en tiempo constante.

Sección 6.3 · Acceso directo por dispersión

6.3 Búsqueda por Funciones de HASH (Tablas Hash)

Esperada O(1)

El hashing (dispersión) sustituye la comparación sucesiva de valores por un cálculo aritmético directo. Una tabla hash almacena pares clave-valor dentro de un arreglo de m posiciones llamadas cubetas (buckets). A partir de una clave k, una función de dispersión h(k) transforma la clave en un índice válido dentro del rango [0, m - 1].

La función debe ser determinista (la misma clave siempre produce el mismo índice), rápida de evaluar en O(1) y distribuir las claves de manera uniforme. El método más clásico para claves enteras es la división modular, eligiendo preferentemente un tamaño de tabla m primo:

h(k) = ((k mod m) + m) mod m   // Garantiza índice no negativo en [0, m - 1]

Manejo y resolución de colisiones

Dado que el universo de posibles claves supera al tamaño m de la tabla, es inevitable que dos claves distintas produzcan el mismo índice (k₁ != k₂ pero h(k₁) == h(k₂)). Este evento se denomina colisión y existen dos familias principales para resolverlo:

Estrategia 1

Encadenamiento (Separate Chaining)

Cada cubeta de la tabla guarda la cabeza de una lista enlazada. Cuando ocurre una colisión, el nuevo nodo se inserta en la lista de esa cubeta. Al buscar, se calcula h(k) en O(1) y se recorre secuencialmente únicamente la breve lista enlazada de esa posición.

Estrategia 2

Direccionamiento Abierto (Open Addressing)

Todos los registros viven dentro del mismo arreglo sin listas externas. Si la cubeta h(k) está ocupada, se explora una secuencia alternativa hasta hallar una celda libre o la clave buscada: sondeo lineal (h(k) + i) mod m, sondeo cuadrático (h(k) + i²) mod m o doble hashing.

Complejidad y Factor de Carga

  • Factor de carga (α): Se define como α = n / m (elementos almacenados entre capacidad). En encadenamiento conviene mantener α ≤ 1; en direccionamiento abierto α < 0.7 antes de redimensionar (rehashing).
  • Caso esperado — O(1): Con dispersión uniforme y α acotado, el costo promedio de búsqueda, inserción y eliminación es constante: O(1 + α) = O(1).
  • Peor caso — O(n): Si una mala función hash envía todas las claves a la misma cubeta, la búsqueda degenera en un recorrido lineal de longitud n.

Integración con Listas Enlazadas

Las tablas hash con encadenamiento combinan lo mejor de ambos mundos: la indexación directa O(1) de los arreglos contiguos en el directorio de cubetas y la flexibilidad dinámica de las listas enlazadas para absorber colisiones.

Ventajas

  • Búsqueda, inserción y eliminación en tiempo promedio constante O(1) independientemente de que haya miles o millones de registros.
  • No requiere que los datos ingresen ni se mantengan ordenados.
  • Ideal para diccionarios, índices de bases de datos, cachés y tablas de símbolos de compiladores.

Desventajas

  • Mayor consumo de memoria inicial para mantener un factor de carga bajo y evitar colisiones frecuentes.
  • No conserva orden entre claves: es ineficiente para búsquedas por rango (ej. valores entre 20 y 50) o encontrar mínimo/máximo.
  • Las operaciones de redimensionamiento (rehashing) al crecer la tabla requieren recalcular todos los índices.

01_BusquedaSecuencial.cs — Arreglo contiguo y Lista enlazada 
using System;

namespace EstructurasDeDatos.Busquedas
{
    // Nodo simple para demostrar búsqueda lineal en estructuras enlazadas
    public class NodoLista
    {
        public int Dato { get; set; }
        public NodoLista? Siguiente { get; set; }

        public NodoLista(int dato)
        {
            Dato = dato;
            Siguiente = null;
        }
    }

    public static class BusquedaSecuencial
    {
        /// <summary>
        /// Busca un entero en un arreglo sin requerir orden previo.
        /// Complejidad: Mejor caso O(1), Peor caso O(n), Espacio O(1).
        /// </summary>
        public static int BuscarEnArreglo(int[] datos, int objetivo)
        {
            if (datos == null || datos.Length == 0)
                return -1;

            for (int i = 0; i < datos.Length; i++)
            {
                if (datos[i] == objetivo)
                {
                    return i; // Retorna el índice donde se encontró
                }
            }

            return -1; // Elemento no encontrado
        }

        /// <summary>
        /// Recorre secuencialmente una lista enlazada mediante punteros/referencias.
        /// </summary>
        public static NodoLista? BuscarEnLista(NodoLista? primero, int objetivo)
        {
            NodoLista? cursor = primero;

            while (cursor != null)
            {
                if (cursor.Dato == objetivo)
                    return cursor; // Referencia al nodo encontrado

                cursor = cursor.Siguiente; // Avanzar al siguiente enlace SIG(P)
            }

            return null;
        }
    }
}
02_BusquedaBinaria.cs — Versión iterativa O(1) espacio y recursiva 
using System;

namespace EstructurasDeDatos.Busquedas
{
    public static class BusquedaBinaria
    {
        /// <summary>
        /// Búsqueda binaria iterativa sobre un arreglo previamente ordenado ascendentemente.
        /// Complejidad: O(log n) en tiempo, O(1) en espacio adicional.
        /// </summary>
        public static int BuscarIterativo(int[] datosOrdenados, int objetivo)
        {
            if (datosOrdenados == null || datosOrdenados.Length == 0)
                return -1;

            int bajo = 0;
            int alto = datosOrdenados.Length - 1;

            while (bajo <= alto)
            {
                // Evita desbordamiento de enteros frente a (bajo + alto) / 2
                int medio = bajo + (alto - bajo) / 2;

                if (datosOrdenados[medio] == objetivo)
                    return medio; // Coincidencia exacta en el centro

                if (objetivo < datosOrdenados[medio])
                    alto = medio - 1; // Descartar mitad derecha
                else
                    bajo = medio + 1; // Descartar mitad izquierda
            }

            return -1;
        }

        /// <summary>
        /// Variante recursiva del método de divide y vencerás.
        /// </summary>
        public static int BuscarRecursivo(int[] datosOrdenados, int objetivo, int bajo, int alto)
        {
            if (bajo > alto)
                return -1; // Caso base: intervalo vacío

            int medio = bajo + (alto - bajo) / 2;

            if (datosOrdenados[medio] == objetivo)
                return medio;

            return objetivo < datosOrdenados[medio]
                ? BuscarRecursivo(datosOrdenados, objetivo, bajo, medio - 1)
                : BuscarRecursivo(datosOrdenados, objetivo, medio + 1, alto);
        }
    }
}
03_TablaHash.cs — Tabla Hash con resolución de colisiones por encadenamiento 
using System;
using System.Collections.Generic;

namespace EstructurasDeDatos.Busquedas
{
    public class TablaHash
    {
        private readonly int _capacidad;
        private readonly LinkedList<(int Clave, string Valor)>[] _cubetas;

        // Se recomienda usar un número primo para reducir colisiones
        public TablaHash(int capacidad = 11)
        {
            _capacidad = capacidad;
            _cubetas = new LinkedList<(int, string)>[_capacidad];

            for (int i = 0; i < _capacidad; i++)
                _cubetas[i] = new LinkedList<(int, string)>();
        }

        /// <summary>
        /// Función de dispersión modular segura para claves enteras positivas o negativas.
        /// </summary>
        private int CalcularIndice(int clave)
        {
            return ((clave % _capacidad) + _capacidad) % _capacidad;
        }

        /// <summary>
        /// Inserta o actualiza un par clave-valor resolviendo colisiones en la lista de la cubeta.
        /// </summary>
        public void Insertar(int clave, string valor)
        {
            int indice = CalcularIndice(clave);
            var lista = _cubetas[indice];

            var nodoActual = lista.First;
            while (nodoActual != null)
            {
                if (nodoActual.Value.Clave == clave)
                {
                    nodoActual.Value = (clave, valor); // Actualiza valor existente
                    return;
                }
                nodoActual = nodoActual.Next;
            }

            lista.AddLast((clave, valor)); // Encadena al final de la cubeta
        }

        /// <summary>
        /// Busca una clave en tiempo esperado O(1).
        /// </summary>
        public string? Buscar(int clave)
        {
            int indice = CalcularIndice(clave);
            foreach (var entrada in _cubetas[indice])
            {
                if (entrada.Clave == clave)
                    return entrada.Valor;
            }

            return null; // Clave inexistente
        }
    }
}
